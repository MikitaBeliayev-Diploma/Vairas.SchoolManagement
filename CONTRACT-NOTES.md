# School implementation alignment

Source hashes are recorded in source-manifest.json. Documentation/Database/school-management provides the thirteen-table canonical schema. D-045 design documents supply invitation policy and replay/activation semantics. The implementation adds one technical coordination table; the current OpenAPI export includes the invitation and Scheduling integration operations beyond the original nine-operation proposal.

- Canonical HTTP routes and operation IDs are retained. The versioned /api/v1 and /internal/v1 prefixes and Idempotency-Key match the existing Auth/UM implementation; the D-045 prose's short routes and Operation-Id are not introduced as conflicting aliases.
- D-045 invitation routes are added under /api/v1/schools/{schoolId}/invitations and /api/v1/users/me/invitations. MutationResponse exposes the typed current resource and a replay flag. Accepted results retain the canonical accepting operation ID.
- Existing POST /internal/v1/profile-provisioning/validate echoes actorUserId/targetUserId/schoolId/invitationId/role/bootstrap and returns allowed/authorityBasis/validUntil plus nullable issuerUserId. For an allowed invitation, issuerUserId comes from the immutable issuing operation and must match the effective Administrator membership when that basis applies. For allowed bootstrap, it is the configured operator's actorUserId. Denied responses expose no issuer. Validation is local-only, has no callback into UM and never consumes an invitation.
- The coordinated UM contract accepts issuerUserId and checks that issuer's primary UserProfile is active before first staff-profile creation. Sorted user locks serialize the issuer check with UM deactivation; no SQL lock spans the School RPC. Existing profiles and saved receipts retain their current replay semantics, including fresh School admission. A global role profile grants no school rights.
- Operator configuration uses canonical UM UserIds. Bootstrap validation is read-only and requires configured operator, Administrator role, existing active school and no effective Administrator membership. It does not activate the first membership.
- Eligibility mutations use durable Scheduling coordination when explicitly enabled. Disabled or unavailable providers fail closed. Recovery resumes Pending, LocalApplied and AbortPending intent; no timeout releases protection. Operator abort requires an audited reason and a verified negative decision; local commit cannot be aborted.
- Enrollment category catalogue, pinned programme and completion evidence remain outside School ownership. A configured platform operator may grant SchoolRuleOwner to an active Administrator or Assessor to an active Teacher. Learning programme applicability requires its real provider; enrollment completion stays gated until its authoritative contract is supplied.
- group_roster_revision and group_roster_member are append-only. Exact historical revision/interval reads never rewrite or substitute current evidence. Current operational reads fail closed on unresolved coordinated operations.
- The canonical DDL is frozen unchanged. The exclusion SQL has only its standalone BEGIN/COMMIT wrappers removed for the EF transaction. Additions include immutable-evidence/invitation/operation guards, self-discovery, and one fourteen-column technical coordination table with a minimal worker queue function. Original thirteen business tables remain retained.
- Initial migration is for an empty database. This is not an upgrade migration for an unknown existing production schema. Runtime grants/RLS are applied explicitly by the migration owner; runtime never owns tables. The trusted application may set a school GUC after resolving its actor and checking local authority; RLS protects omitted predicates, not a compromised service deliberately forging trusted scope.
- Structured logs contain method, route template, response status, duration, correlation ID and safe failure code/type. Audit operations retain actor/binding/outcome without credentials or full payloads.
- No School MCP mutation delegation, Azure Service Bus inbox/outbox, SMTP or Learning provider is added. The neighboring Scheduling service is implemented and its owner coordination is exercised through four actual in-process HTTP pipelines. Shared Communication contracts are explicitly re-exported; original database DDL remains unchanged. The issuer response amendment is coordinated with the local User Management implementation.
